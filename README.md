# geographiclib-mgrs

This is a JavaScript port of the MGRS functionality in GeographicLib. It is designed to be a drop in replacement for proj4js mgrs.

Differences between geographiclib-mgrs and proj4js mgrs:

- GeographicLib MGRS supports
  - UTM zones
  - UPS zones
- Proj4js MGRS supports
  - UTM zones

## Installation

```
npm install geographiclib-mgrs --save
```

## Usage

```js
import MGRS from "geographiclib-mgrs";
```

to convert a MGRS string to a point

```js
const mgrs = "42SUF1230045600";
// optional variable if you want to use the center point or lower left
// default value is true
const centerpoint = false;
const point = MGRS.toPoint(mgrs, centerpoint);
// return [long, lat]
```

to convert a latlong to a MGRS string

```js
const point = [long, lat];
const accuracy = 5;
const result = MGRS.forward(point, accuracy);
// return MGRS string
```

to convert a MGRS string to a bounding box

```js
const mgrs = "42SUF123456";
const point = MGRS.inverse(mgrs);
// return [lowerLeft.lon, lowerLeft.lat, upperRight.lon, upperRight.lat]
```

It is also possible to access the underlaying geograpiclib functions under `MGRS.MGRS` and `MGRS.UTMUPS`, where most methods from geographiclib are aviable.

For example:

```js
MGRS.MGRS.reverse(mgrs, true);
/* returns object
 * zone: UTM zone (zero means UPS).
 * northp: hemisphere (true means north, false means south).
 * x: easting of point (meters).
 * y: northing of point (meters).
 * prec: precision relative to 100 km.
 * */
```

## Verification

Run `npm test` to check the port against committed results generated by unmodified GeographicLib C++, as well as the existing GEOTRANS comparison tests. A C++ compiler is not needed for the regular test suite.

The port follows GeographicLib's double-precision, sixth-order transverse Mercator implementation. MGRS strings, zones, hemispheres and precisions are checked exactly; floating-point coordinates, convergence and scale are checked within explicit numerical tolerances because JavaScript and C++ math libraries can differ in their last bits. GEOTRANS differences are diagnostic and do not define the expected GeographicLib result.

See [the C++ parity review and reproduction instructions](test/reference/README.md) for findings, compatibility changes, test coverage and limits. The `inverse` convenience function projects the southwest and northeast grid corners; these two points do not necessarily bound the entire geographic footprint of a rotated or polar grid square.
